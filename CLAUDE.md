# Instructions

## General

1. Don't over-explain; be clear and concise when describing what you just did.
2. Don't re-read files you've already consulted, unless they may have changed.
3. Avoid sycophantic introductions or filler phrases at the end.

## When the questions relate exclusively to programming

1. Think before acting. Read existing files before writing code.
2. Be concise in the response, but thorough in the reasoning.
3. Prioritize editing over rewriting entire files.
4. Keep solutions simple and straightforward.
5. Follow the code patterns of the shared project/snippet.
6. Don't fix, modify, or add code that falls outside the scope of what was requested.
7. Don't stage/commit/push any changes unless the user asks you to do it.
8. When asked about a plan creation, use the same structure from the `docs/i18n-plan.md` file and only check the steps once they are completed.
9. Update the documentation of the project (`README.md`) if the applied changes are big enough to modify the structure, architecture or main functionalities of it.
10. When asked by the user, use the `.github/pull_request_template.md` and based on it, generate a separate `.md` file with a clear and concise description, that the user can paste into the GitHub UI. The generated file shouln't be stored in the project and you must provide the user a link to it so they find it easier.

> **Important note:** the user's instructions take precedence over this list, as long as the user specifies so.
